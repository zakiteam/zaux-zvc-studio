## Runtime CSS overriding static responsive classes — 2026-10-07
Symptom: classes inside Zaux templates such as FeatureSection (`hidden md:block`, `block md:hidden`, `grid-cols-1 md:grid-cols-2`) appeared overridden by a <style> block. Cause: `/api/preview-css` re-emitted every class found in the document JSON (including words like `hidden`/`block` in text or prop values) into the iframe <style>, after the static CSS, so base utilities beat the static responsive variants used by templates. Fix: `scripts/zaux/static-classes.mjs` writes `generated/static-classes.json` (15663 classes on the installed release, ~4 s in prepare); `integrations/zaux/runtime-classes.js` filters runtime candidates against it and the endpoint compiles only the rest (empty CSS when nothing is missing). The list refreshes on each prepare; Studio app class edits during a dev session are picked up at the next start. `npm run prepare:zaux` was run; the endpoint itself was not exercised, no tests or browser checks.

Cause: the shortcut helpers bail out when the document contains `[role="dialog"][aria-modal="true"]` (or the target is inside `[role="dialog"]`); in the iframe that document is the authored page, and Zaux OffCanvas/ZModal keep those attributes in the DOM while hidden (`v-show`), so any template with such a component disabled every canvas shortcut. `app/services/node-shortcuts.js` helpers now take `{ authored: true }`, which counts only native `dialog[open]`; `app/pages/preview.vue` passes it (`AUTHORED`). The Studio document keeps the stricter checks. Reviewed by source reading only.

Outline hierarchy (2026-10-07): `BuilderTree` gains a `nested` prop that applies the nested indent and guide line without changing `depth` (still used for the free-root Group into ZVC item); `BuilderSidebar` passes it for the nodes under a ZVC instance heading and under the edited definition, so first-level nodes are indented below their owner. Free elements stay at the root. Source reading only.

## install:zaux EPERM on Windows — 2026-10-07
`npm run install:zaux` failed with `EPERM: operation not permitted, rename 'vendor/zaux.staging' -> 'vendor/zaux'` while the Nuxt/Vite dev server (HMR :24678) held brief locks on the freshly written staging files, leaving `vendor/` empty. `scripts/zaux/install.mjs` now retries the swap's `renameSync`/`rmSync` on `EPERM`/`EACCES`/`EBUSY`/`ENOTEMPTY` with backoff (`renameWithRetry`/`removeWithRetry`), keeps the atomic backup/restore, and appends an actionable hint to stop the dev server if the lock persists. Verified by re-running `npm run install:zaux` (installed v2.5.1 from `.env` `ZAUX_VERSION`); `vendor/zaux/core/setup.js` restored.
